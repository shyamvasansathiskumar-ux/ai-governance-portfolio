# ai-governance-portfolio

Written work on AI governance, risk, and assurance — risk assessments, policy artifacts, and published analyses.

**Shyam Kumar** · CSE, Rajalakshmi Engineering College · started August 2026

Deliberately separate from [`redteam-log`](../redteam-log). That repo is a lab notebook; this one is finished work meant to be read. Governance hiring rarely looks at GitHub at all — this repo exists so that when someone *does* look, they find writing rather than scan dumps.

## What lands here, and when

- **Week 9** — that assessment published as policy analysis #1
- **Week 11** — policy analysis #2
- **Week 12** — the documented LLM vulnerability audit, written for a governance reader

## Standard for anything in `analyses/`

1. **Narrow beats broad.** "How [specific product]'s [specific feature] maps to EU AI Act transparency obligations" is a piece. "AI governance is important" is not.
2. **Every claim is sourced.** Link the framework clause, the regulation article, the vendor documentation. Unsourced assertion is the single fastest way to lose a technical reader.
3. **Say what you'd do.** Analysis that stops at "this is a risk" is half-finished. Name the control.
4. **Assessments of real products are external, black-box, and clearly labelled as such** — based on public documentation and observable behaviour, not privileged access, and never presented as an official or commissioned audit of that company.
