# analyses/

Finished, published pieces. One file per piece, named `YYYY-MM-DD-short-slug.md`.

## Before publishing, check

- [ ] The claim is narrow enough to defend in a comment thread
- [ ] Every factual assertion links to a source
- [ ] There is at least one concrete recommendation, not only diagnosis
- [ ] Someone technical would not find it naïve; someone non-technical would not find it impenetrable
- [ ] Any assessment of a real product carries the external/black-box scope note
- [ ] It says something you actually believe

## Piece structure that works for this audience

1. **The specific thing that prompted it** — a clause, an incident, a product change
2. **Why the obvious reading is incomplete**
3. **What the framework actually requires** — cited
4. **What you'd do about it**
5. **What you're uncertain about** — this builds more credibility than confidence does
